# v1.5.1 — Shared-Client Usage Trends Restored

## Highlights

- The Usage chart plots observed local token history again. The previous release
  read only the legacy OpenCode `message` table, which stopped receiving rows
  when OpenCode moved to `session_message`; the chart therefore rendered a flat
  zero line while the frames themselves were healthy.
- Usage is now combined across **OpenCode, Codex, and Hermes** regardless of
  which app is currently in front, because all three can consume the same
  DeepSeek and OpenAI accounts.
- OpenAI input tokens are counted independently of model pricing. Models with no
  known rate still plot; their cost contribution makes the weekly estimate show
  **unavailable** instead of a false zero.
- Recovered history is written back idempotently, so hours that occurred while
  the widget was not running appear on the chart after the next refresh.

## Behaviour and data boundaries

- OpenCode V2 and legacy V1 message rows are read together. A migrated message
  ID prefers its V2 row without losing V1-only messages.
- Codex reads `session_meta`, `turn_context`, and `token_count` events, including
  fractional-second timestamps, per-session cumulative baselines, archive copies,
  and exact replays. Provider attribution comes from declared metadata, not from
  model-name guessing. Custom proxy base URLs stay excluded, including across
  later turns that only repeat the same provider name.
- Hermes rows are routed by `billing_provider` and canonical base URL. Its totals
  are cumulative and attributed to `last_seen`, so a growing row moves between
  hours rather than being added twice. That remains an approximation of the true
  per-hour distribution.
- A failed or still-missing optional app never blocks healthy sources. Failed
  reads keep their previous observations, and the menu shows an incomplete-history
  note instead of silently plotting zero.
- Local provider metadata identifies providers, not the authenticated billing
  account. The chart is an observed local history, not authoritative account-wide
  quota consumption or an invoice. Remote-only activity cannot be reconstructed.
- A flat DeepSeek line can be correct when no supported local DeepSeek usage falls
  inside the visible week.

## Verification

- 248 tests pass across all four test suites, including new coverage for V1/V2
  coexistence, Codex date/model/proxy handling, cumulative counters and archive
  replay, cross-client deduplication, historical backfill, partial-source safety,
  and retention.
- Unsigned universal `arm64` + `x86_64` Release build succeeded.
- Protected read-only snapshots of the real source databases were reconciled into
  an isolated temporary ledger and projected through the chart three times with
  identical results, including a non-zero OpenAI series.
- The installed app was then replaced with this build and verified live: the
  existing ledger was preserved, the new provenance tables migrated additively,
  and the visible 168-hour window contained non-zero OpenAI and DeepSeek buckets.
- No prompts, credentials, conversation content, or private source payloads are
  logged or stored by the readers.
